# The command contract

What every mutating command of `next/` promises its callers — people at a terminal, scripts, agents, other surfaces. A command keeps it through the shared pieces (`service/operation`, `ui/cli`, `ui/output`, `ui/form`, `api`); a deviation is an owner decision listed in its PR.

## Inputs

- A run is its `Request` (the command's fields, snake_case JSON tags) plus `domain.RunOptions` (`DryRun`, `ExpectFingerprint`, `Surface`, `CorrelationID`, `Report`). Everything a run depends on travels with it, so one process can serve several callers and repositories: the repository is the directory the use case is opened on (`open(ctx, dir)`, resolved to its main worktree), `--ask` is the request's `ask` field, the correlation ID is recorded by `operation.Service.Begin` on the operation and every event.
- The process environment is read once, at the edge: `ui/cli.ReadEnv` (working directory, `$WTM_PROJECT_DIR`, `$WTM_CORRELATION_ID`, an invalid one refused before any repository lookup), `ui/output.System` (which streams are terminals, `$TERM`), `$WTM_STATE_DIR` in `cmd/wtm-next/project.go` (`movedState`, its one reader). A command line whose working directory cannot be read, with no `$WTM_PROJECT_DIR`, is refused by `uicli.Run.Begin` (`cli.no_working_directory`, exit 25): it cannot tell where its caller stands. An adapter reads only what its own tool needs (`os.UserConfigDir`, a child's environment). Domain, services and commands never read it. `[archlint]` (`envread`)
- Where the caller stands is one value, `domain.Caller{Dir, Named, Cwd}` (`domain/caller.go`): `Dir` the directory the command runs on, `Named` whether the caller chose it, `Cwd` the directory the caller is in, from which a relative path it gives is read and the worktree it stands in is found. A request that needs it implements `domain.ReadsCaller` (`From(caller) Request`, a field `Caller` tagged `json:"-"`, never a field of its form) and every surface sets it through `domain.CalledBy`: the form engine from `uicli.Env.Caller` (`$WTM_PROJECT_DIR` or the working directory, the working directory), `api.Bind` and `api.BindStream` from the call (`Dir`, named, `Cwd` = `Dir` with its symbolic links resolved, as git spells the worktrees it lists; a stream's call naming no directory stands nowhere). No cli wrapper sets it. `[test]` (`api/catalogue_test.go`, `domain/caller_test.go`, `cmd/wtm-next/registration_test.go`)
- The subject is positional (`create [branch…]`, `extract [source]`); a worktree that is not the subject is a flag named after its role (`--to`, `--from`). A flag whose absence means something (`--ff`) is a pointer in the request, set only when given.
- config.toml is validated at load (`adapter/config`): a file that does not parse or validate, an absolute `base_path` among them, refuses the run with `<command>.config_invalid` (precondition, exit 1, `invalid config.toml: <reason>`), as no config is `<command>.config_not_found` (exit 12, `no wtm config found`, `wtm init` as its `error.follow_up`); `repository.Service.Observe` raises both, the suffixes `domain.ConfigNotFound` and `domain.ConfigInvalid` after the command's name.
- A field error names its path; the CLI spells it as its flag (`--files is required`, `<branches>[1]`).

## Interactive or unattended

- Interactive only when stdin and stderr (where the wizard draws) are terminals, `$TERM` is not `dumb`, the output is human, and neither `--yes` nor `--expect-fingerprint` is given (`output.Streams.CanPrompt`). Live progress needs only stderr a terminal (`CanAnimate`).
- Unattended otherwise: a field with a default takes it, a required field without one is a refusal naming its flag — never a picker. `--output json` is unattended by nature.
- `--yes` (`-y`), the confirmation axis: no question; each open decision takes its flag, else its remembered answer, else a documented safe default, never destructive.
- `--force`, the safety axis: it only lifts a safety refusal (dirty, unpushed, locked). It never implies `--yes`.
- A safety refusal depends on who chose the worktree: one the request names refuses the whole request (`KindRefused`, `<command>.unsafe`, a problem per blocker on its entry, the request forced as follow-up, `<command>.force`); one the command chose itself (no `worktree` answer: the wizard's default pick confirmed untouched, an unattended run naming none, fast-forward's and sync's `--all`, sync's descendants of a worktree named) is left as it is, a plan entry with its blockers and no phase, `skipped` with `domain.ReasonRuledOut`, a warning per worktree, the last followed by one request forcing them all, and the others go on. The default pick leaves it out. `next/README.md`, "A worktree named, a worktree the command chose".
- A worktree whose meta record a newer wtm wrote is never written by this one: deleting or rewriting the record is a write, and what it means is that wtm's to know. Named to clean, prune or reparent, it refuses the whole request before anything changes, forced or not (`KindPrecondition`, `<command>.meta_newer`, `domain.MetaNewer`, exit 22); one prune chose itself is left as it is with a `prune.meta_newer` warning and no follow-up, since no force lifts it, and the others go on; create and extract refuse a plan that would number a new worktree past such a record before anything is made (`<command>.meta_newer`, `provision.Service.NewerNeighbours`: the ordinal it holds is not known), the numbering itself failing its worktree only on a record that turned newer since the plan. A record that merely does not decode keeps its own path: removed with its worktree, skipped by the numbering.
- A remembered answer (`config.toml` `[wizard.remembered]`, written by "always use this answer" or `--remember <field>`) stands in for the flag not given; `--ask` sets the memory aside for one run.

## Dry run and fingerprint

- `--dry-run` (`-n`) plans without a lock, an event or a change, and prints the plan, its warnings, its fingerprint and the line that applies exactly this plan (`… --expect-fingerprint <fp>`).
- `--expect-fingerprint <fp>` applies only if the facts, read under the locks, still give that fingerprint; otherwise `plan.stale` (exit 25), with the `--dry-run` that plans again as a follow-up (`plan.replan`, `domain.Replan`).
- The fingerprint covers what the plan does (which files, their status), not the files' bytes.
- The wizard's recap is a dry run, applied with its fingerprint; a stale preview asks again. A plan that changes nothing (`domain.Recapped.Empty`, set by the use case beside its recap, published in the plan) is not asked to be confirmed: the wizard finishes at the preview and the apply says nothing was to do (`Script.Empty`, from `Outcome.Empty`); unattended, it applies nothing and exits 0.

## Output

- Human output is framed once (`output.Frame`) on stdout; progress, hook output and warnings during the run go to stderr; a refusal is framed on stderr. Colour is decided per stream (`NO_COLOR`, `TERM=dumb`, not a terminal).
- A plan's recap is data: the plan embeds `domain.Recapped`, the use case setting `plan.recap` (`[]domain.RecapRow`, its JSON in the `catalogue_*_dry_run` goldens) and `plan.recalled`, and on apply the applied recap with `saved` marks (`Plan.applied` in `rules.go`); the fingerprint leaves both out. The cli previews it with `form.PreviewOf` and draws an apply with `output.DrawApplied`, the one drawing of every mutation: the tally (its note, extract's `plan.summary`, a coded value of the plan), the applied recap with a row per worktree that stands, the warnings, each unfinished item, the next steps. An outcome's anomalies are warnings of their item, decided by the use case: each drawn `subject  message`, an item done's in the plan block, an unfinished item's right under its own line, the table of the env ports an item's warning carries (`ports`, provision's ports left alone, an `env.LeftAlone`, redacted) under it, and its `follow_up` as a next step (`output.WarningMessages`, `output.WarningSteps`); a run's own warnings, drawn after the items', and a preview's carry no `ports` but may carry a `follow_up`, drawn after the items' steps, and after the line that applies the plan on a dry run: a plan decides them, and what it ignores may be what the reader wants done another way (extract's `isolation_ignored`, followed by the `env` that switches it), never chosen by code. A warning carries a typed field of `domain.Warning` only when a surface draws or acts on it and a second warning could carry it too (`follow_up`, `ports`); a fact that only qualifies its message goes in `params`, and a field one warning alone needs is a sign the warning is an item's detail instead. The next step an outcome ends on is a follow-up of its result (`next` in each command's `rules.go`), drawn as it comes.
- Success contracts to a count, anomalies are named one by one, every outcome ends with the next step (`→ wtm go <branch>`). A flag error prints the failure and one line pointing at `--help`, never the usage dump. `-q` silences human output, not errors, exit codes or JSON.
- `--output json` prints one v2 envelope on stdout and nothing else: `{v: 2, command, ok, op, items[{subject, status, reason, error, warnings, detail}], plan, fingerprint, follow_ups[{command, answers[{path, values}], dry_run, url, code, message, params}], warnings[{code, params, message, follow_up, ports}], error{kind, code, message, params, follow_up, fields[{path, code, flag, message, follow_up…}]}}`. `Outcome.Envelope(domain.EnvelopeParams{Command, Err, Answers})` builds it, a stale plan followed up by its replan, for the CLI and the catalogue alike (`Read.Envelope` takes the same params and has no replan); `domain.Envelope.JSON(spell)` writes it with each refused field spelled as the surface does (an API passes nil: the flag is the path).
- A step offered after the outcome (sync's "push now?", clean's retry with sudo) is a second exported entry of the use case, with its own request, operation and fingerprint, run like the first. The first never runs it: it returns a `domain.FollowUp{Command, Answers, DryRun, Code, Message, Params}`, on a failure in `error.follow_up`, on a field error in its `follow_up` (create's branch checked out elsewhere, followed by the `go` that jumps in: the CLI prints it after the failure, the wizard under the step's inline error), on a warning in its `follow_up` (provision's ports not settled), else in `follow_ups` (a stale plan's replay, `DryRun` set, `domain.Replan`): the wtm command it names, by its name in the catalogue (`create`, `run-up`, which the command line spells `run up`), and its request as that command's answers, which a surface runs through the catalogue unchanged; a link to open instead has a `URL` and no command (list's pull request). `FollowUp` is deliberately one wire struct of these two shapes, not a sealed union: a surface tells them apart by `command` or `url`, and a JSON consumer reads one object type. Its `message` is an optional note, the one the CLI prints beside the command line (empty for a plain step into a worktree): a surface labels a follow-up by its `code`. The JSON never carries a command line: the CLI spells a follow-up at print time with the one `output.CommandLine` `cmd/wtm-next` hands to each cli's `New`, through `output.FollowUpStep`/`FollowUpSteps`, and a test fails on an answer it cannot spell; and `form.Command.Bind` composes the one speller its run draws with (a failure, `-q` included, the wizard, a dry run, the outcome): a follow-up naming the command itself, its replan or extract's conflict followed by the answers given with `on_conflict=resolve` (`extract.resolve`), is spelled from its own schema (`Argv`, `--dry-run` when asked), any other by the injected `CommandLine`, which spells the commands not migrated; a command slice may name another command in a follow-up it builds from what it decides (list's actions, create's and extract's step into a worktree, extract's `env` that switches an existing target's isolation), a shared service never does: `cmd/wtm-next` injects its follow-up (`provision.Service.LeftBehind`, `Settle` and `ProxyStatus`, `repository.Service.Init`), the service setting its code and message; `uicli.Run.FailWith` prints a refusal's follow-up as a next step, which `-q` keeps (`output.QuietFailure`), since it is the way out of the error; and `registration_test.go` fails once a command a follow-up names has migrated.
- A surface also receives the request (its tags), its schema `domain.Form` (each field with its `kind`, then the request's problems; how a surface groups the fields, a wizard's steps or a page's parts, is the surface's own) and the events (`domain.MarshalEvent`); on the event bus each event is a line of the v2 stream (`domain.MarshalLine`: the envelope `v`, `type`, `ts`, `repo`, `correlation_id`, `op_id`, then the event's fields), the schema `adapter/events/events.v2.json`.

## The catalogue

`api.Catalogue` (`next/internal/api`) lists the commands for a surface other than the CLI, one `api.Bind(name, open, questions, run)` per command in `cmd/wtm-next/catalogue.go`, its `Form` the schema of zero questions. A call's request is its `Answers` (`[{path, values}]`), its only input, folded by `Request.Answer` as the command line folds its flags. `Questions(ctx, call)` returns the form as the repository stands for that request (options, remembered answers, problems by path), what a surface renders and asks again after each answer. `Execute(ctx, api.Call{Dir, Answers, Options})` refuses a relative `Dir` (the directory the use case opens on and where the caller stands, "Inputs"), refuses an answer by its path (`request.invalid`, `fields`), runs it, follows a stale plan up with its replan (its answers as a dry run, through the same `Outcome.Envelope` the CLI uses), (`Surface` defaults to `api`) and returns `api.Response{Status, Envelope}`: none 200, `invalid` 400, `refused` 403, `conflict` 409, `precondition` 412, `cancelled` 499, `internal` 500.

### The catalogue contract

Every command of the catalogue is driven by `api` alone, nothing of its `cli`: `cmd/wtm-next/contract_test.go` runs each over the real adapters on a repository configured for wtm, a mutation from `mutations()`, a read from `reads` (`fixture_test.go`), and fails on a command in neither. `[test]`

- **A mutation:** an empty request is asked its subject (a problem on the first answer's path), `Questions` of its answers leaves none; their form's `Answers()` previewed (`DryRun`: a fingerprint, a plan, no item); the facts changed (`stale`), the same answers held to that fingerprint are refused `plan.stale` (412), applying nothing, with one follow-up, its replan, a dry run of the same command; that replan run gives a new fingerprint; its answers held to it apply, every item `done`.
- **A read:** `Questions`, then the read of their answers: 200, items, no `op`, `plan` nor `fingerprint`, no operation recorded.
- **The shapes:** each JSON document of the run, the zero `Form`, the questions, each envelope and the events of the apply, is compared with `testdata/catalogue_<command>_<part>.golden`, ids and times as placeholders: the published shapes a surface's types are generated from. A change to one is a change to the contract, reviewed as such. The `envelope_*` goldens of each command's `cli/testdata` complete them for the shapes the contract cannot reach (`error.follow_up`, a pull request), and `catalogue_create_invalid_*` for a refused call (`error.fields`, 400).

- **The published schema:** `next/internal/api/api.v2.schema.json` (JSON Schema 2020-12, `api.Schema()` serves it) describes every shape a surface receives, under `$defs`: `domain.Envelope`, `domain.Form` and `domain.Field` (one of its kinds, by `kind`), `domain.Event` and `domain.Line` (`$ref`s to `events.v2.json`, whose `$defs/event` is the union of every type), then `<command>.request` (the answer of each field of its form by path), `<command>.envelope` (the envelope with its `command`, its `plan`, none for a read, and each item's `detail`), the same request and envelope for each stream (`events.request`, `events.envelope`, no plan nor item: its lines are `domain.Line`) and each type a plan or a detail reaches, reflected from its Go type under `<package>.<Type>`: closed, a field without `omitempty` required, null where encoding/json writes a nil as null. A type whose `MarshalJSON` writes its JSON by hand (`Form`, `Answered`, `Envelope`, `*Error`, `FieldError`) has its fragment written beside it (`domain/form.schema.json`, `domain/envelope.schema.json`); the web server's own routes have theirs beside the server (`web/web.schema.json`: `web.Version`, `web.Repos`, `web.Commands`, `web.Call`, `web.Warning`, `web.Busy`, `web.CommandLine`, `web.Refusal`), checked against its real responses; and a sealed union's discriminant is read from what its `MarshalJSON` writes. `api.Bind` keeps a command's plan and detail types (`Outcome.Types`). `make schema` regenerates it (`cmd/wtm-next/schema_test.go`, `-update`); `make test-next` fails while it is stale, validates against it every `catalogue_*` golden and every `envelope_*` golden of a command's `cli/testdata`, and refuses a follow-up of a golden (`follow_up`, `follow_ups`, a problem's `fix`, a worktree's `actions`) that says nothing (an empty `message`). `site/scripts/sync-docs.mjs` publishes it, with `events.v2.json`, on `wtm.sh/schemas/`. `[test]`

A new command enters the contract with one entry: a mutation in `mutations()` of `cmd/wtm-next/fixture_test.go` (its answers, the subject's first, what it needs first, what makes its preview stale, what a refused apply leaves as it was, what its apply leaves), or a read in `reads`; `go test ./cmd/wtm-next/ -run Contract -update` writes its goldens, and `make schema` its definitions in the published schema.

## Exit codes

| Code | Meaning |
| -- | -- |
| 0 | success, nothing to do, dry run |
| 1 | an item failed, an invalid config.toml (`<command>.config_invalid`), or a failure no other code names |
| 2 | invalid request (usage, field errors) |
| 12 | no wtm config (`<command>.config_not_found`, read by its suffix) |
| 15 | extract's conflict (`extract.conflict`) |
| 19 | cancelled (Ctrl+C once, a wizard left) |
| 21 | not a git repository |
| 22 | a state file written by a newer wtm |
| 23 | refused |
| 24 | conflict (a lock held, a worktree in the way) |
| 25 | precondition (`plan.stale`) |
| 130 | a second Ctrl+C: the process dies by the signal |

The kind decides (`ui/cli/exit.go`), after the codes every command shares, whole (`git.not_a_repository`) or as a suffix (`<command>.config_not_found` 12, `<command>.config_invalid` 1); a command maps only its own codes in its `cli/` through `uicli.Run.Exits` (extract's conflict, events' newer stream). `ui/cli/exit_test.go` pins the codes wtm shares with the legacy `wtm`.

## Locks, events, cancellation

- A mutating command runs inside an operation (`service/operation`): a record under the state directory, a shared lock on the repository, an exclusive lock per worktree, taken before observing; a plan naming a worktree the request did not is planned again once that lock is held. A dry run takes none.
- Events (`operation.*`, `unit.*`, `phase.*`, `worktree.created`/`provisioned`/`updated`/`removed`) go out through the operation's report; `phase.*` and `phase.output` stay in the process, the others are published on the event bus (`unit.started` too, so another surface knows which worktree an operation works on) (`adapter/events`, best effort, never starting its daemon). A command adds an event only for a change another process must see, as a `domain.Event` variant with its type in the v2 schema.
- The first Ctrl+C cancels the context: the section in progress finishes (a shield), later items are skipped as interrupted, exit 19; the second kills the children's process groups. Details: `next/README.md`, "Cancellation".

## A read

A command that changes nothing, `command/list`, `command/status` or `command/tree`, keeps this contract in place of the operation's.

- `Run(ctx, req, opts)` is `Observe(ctx, req) (Facts, error)`, then the pure report of the facts; the reads share their I/O through `service/repository` (`Records` the meta records, `Present`/`Gone` a worktree's directory, `Ask` the run daemon and the forge while `Each` reads the worktrees, into a `repository.Asked`; `Interrupted` a count cut short) and their pure pieces through the domain (`domain.Unread`, `worktree.Worktree.Name`, `worktree.Repository.CountedAgainstBase`), each command keeping its own codes. `[review]`
- `Run(ctx, req, opts)` returns a `domain.Read[Detail]`, the signature `api.Bind` binds: one `Unit` per subject (`done` with its detail, `failed` with the error that kept it from being read, `cancelled` once the context is), the warnings, the follow-ups chosen. `[test]`
- It takes no lock, runs no operation and publishes no event: its envelope has no `op`, `plan` nor `fingerprint`, and it has no `contract_test.go` of its own. `[test]` (`cmd/wtm-next`, the catalogue contract's read)
- Its `cli` is a `form.Query`: the flags of its schema and `--output`, none of `--yes`, `--dry-run`, `--expect-fingerprint`, `--remember`, `--ask`. `[test]`
- It may print machine formats of its own besides json (`form.Query.Formats`, tree's `mermaid`), drawn by its `cli` from the read: unframed on stdout and never silenced by `-q`/`--quiet`, as JSON is; named in its `--output` usage and in the refusal of an unknown format; a refusal under one is printed in full, as text, on stderr, `-q` or not. `[test]` (`ui/form/read_test.go`)
- What it cannot ask (a forge, the run daemon) is a warning under its own code, exit 0, the fields it would fill `null`; it never starts the run daemon. `[review]`
- One policy for what a read cannot read: a meta record that exists but does not decode, or that a newer wtm wrote (`*domain.SchemaNewer`: what its fields mean is not known, so nothing is shown from it), is a warning on its item, `<name>.meta_unreadable`, the item read all the same; a worktree whose directory is gone, prunable or locked (`repository.Gone` asks the disk), is a done item saying it is missing, never a failure; an interrupted read says it was interrupted and nothing more: it ends cancelled, exit 19, even once every subject was read (`domain.Read.Interrupted`), with none of the warnings of what it could not ask (`repository.Asked.Warnings`); a subject it failed to read is `domain.Unread`, `<name>.unreadable`, or cancelled. Its `cli` closes on `output.ReadEnd`: each subject not read, each item's warnings, then the read's. `[test]` (each read's `usecase_test.go`)
- It exits with the code of its interruption, else of its first subject not read, after a pick too. `[test]`
- Its subject (`status`'s worktree), a positional select its questions leave open (no argument, no `Skip`, nor a `Skips` of the request; tree, which takes no positional, has none), is asked before the read with `form.Subject` under the same condition as the picker below, the cursor on the field's value; anywhere else the use case takes that value itself (the worktree the caller stands in, `Caller.Cwd`: the command line's working directory, a surface's call's directory). A subject the read refuses as ambiguous (a field error coded `domain.CodeAmbiguous`) is asked the same way among the options its questions narrow it to, then read; anywhere else the refusal stands, exit 2. Leaving it is `cancelled`, exit 19. `[test]`
- A read whose text a shell captures (`Query.Captured`, resolve's path for `cd "$(wtm resolve x)"`) draws it bare on stdout, never framed nor silenced by `-q`, its failure on stderr, and asks its subject even while stdout is captured. `[test]` (`ui/form/read_test.go`)
- Its picker (`Query.Pick`) opens only when stdin, stdout and stderr are terminals (stdout aside for a `Captured` read), the output is human and `--quiet` is off; it walks `form.Script` steps with no recap (`Preview` nil), `Later` for a slow read, `Refresh` for `r`, and ends on one of the follow-ups its detail offers (list's `detail.actions`, each a command and its answers, spelled at print time); leaving it is `cancelled`, exit 19. `[test]`

## A stream

A command that never ends on its own, `command/events`, keeps this contract in place of the operation's and the catalogue's.

- Its use case is `Watch(ctx, req, out)`: each line goes to `out.Emit` (its error ends the stream with it), what kept a line or a repository away for a while to `out.Warn`. It returns nil once ctx is done after its first line, ctx's error before (exit 19), else the refusal or what ended it. It runs no operation and changes no repository; what it writes is the registry's (`service/registry`, concrete): the repository it watches, once its config is read, joins `repos.json` (`registry.Service.Register`, announcing `repo.added` when new), and the stream of every repository prunes it at each poll, every `Recheck` (announcing each `repo.removed`); a repository the global stream joins is opened without registering. A repository is initialized while the state directory `cmd/wtm-next`'s `stateDir` gives holds a `config.toml` (`config.Project.Initialized`); the registry is left alone while the state directory is moved (`$WTM_STATE_DIR`, `registry.Service.Moved`): none joins it, none leaves it, it lists none, and the global stream joins no repository another process announces on the bus (`registry.Service.Inert`), since a repository read with a moved state would be read with another's config and records. A line of another version than its own is dropped with a warning (an older one) or ends it (a newer one). `[test]`
- It is built once in `cmd/wtm-next/wire.go`, not per repository in `app`: it opens each repository it watches through a port (`events.Open`, `openEvents`, over the same pieces `wire` builds). `[test]` (`registration_test.go`, `streamsListed`)
- What it watches is its use case's decision (`scope`), from its request and where its caller stands: `--all`, or no `--repo` from nowhere (a surface's call naming no directory, the every-repository stream) or from a directory the caller did not name in no repository, is every repository; a relative `--repo` is read from `Caller.Cwd` (the command line's working directory, never `$WTM_PROJECT_DIR`; a call's directory), from nowhere it is `events.not_a_directory`. `catalogue.go`'s watch only relays lines. `[test]`
- Its `cli` is a `form.Stream`: the flags of its schema and `--output`. It prints each line itself, never framed: JSON Lines with `--output json`, a line of the `ui/output` kit per change otherwise; `-q` silences the lines, never the warnings. A refusal before the first line is the standard failure (the envelope on stdout with JSON); a failure after it goes to stderr, stdout carrying lines alone. Its reader leaving (`output.Stream.Gone`, a pipe or a socket; a write's EPIPE, `uicli.FailOnBrokenPipe`) ends it with exit 0, as an interrupt does. `[test]`
- It is out of the catalogue: `cmd/wtm-next/catalogue.go` lists it in `streams()` (`api.BindStream`, the watch the web server streams as `GET /api/events`; its `api.Sink` carries the lines and the warnings), and `registration_test.go` fails on a stream missing from `streamsListed` or the reverse. `[test]`
- Its shape is a snapshot of each repository watched, `ready`, then changes, each an upsert of a worktree's identity keyed by its branch; a snapshot is a reset. The changes are what the bus carries (an operation's `worktree.*`, `operation.*`, `unit.started` and `unit.finished`, which name the worktree it works on, `repo.*`) and what the stream polls every `Recheck` (5 seconds): the branch's tip, the checkout (a rebase, a bisect), the jobs and whether it holds uncommitted changes of each worktree, read with no operation of wtm — a commit, a checkout or an edit from a terminal, a job started — each sent as `worktree.changed` naming what moved (`head`, `checkout`, `jobs`, `dirty`; a worktree new to the poll has all four), a worktree gone as a fresh snapshot. The poll is light: the worktree list and the branch tips (`events.Git`), a `git status` per worktree one at a time every fourth poll (20 seconds, the legacy dashboard's cadence: 20 worktrees cost a CPU-second), after the other fields are sent, its result dropped when an operation of wtm started while it read (the lines that arrived meanwhile are routed first), and at once for a worktree new to the poll or named by an operation that finished, the jobs (the `Jobs` port, the run daemon), and `config.toml` for a stream of one repository; the full read (`repository.Service.Observe`, the meta records) runs for a snapshot and when the poll found a change, to name it. It never sends what an operation of wtm changed: from `operation.started` to `operation.finished` on the bus (10 minutes at most, its process may have died) it does not poll that repository; at the finish of the last one it reads it again and sends what changed meanwhile, but for the changes of the branches the operations' events named (`worktree.*`, `unit.finished`), theirs; a worktree gone is always sent, as a fresh snapshot, the `worktree.removed` the bus relayed or not. Jobs the daemon cannot tell, and a dirtiness git cannot read, are taken as they were; a missing worktree is not dirty. A reader that shows more than identities (the web's worktree table) reads `list` again after `ready` and at each change. `[test]`
- It reconnects on its own when what it reads goes away (a backoff from 200 ms, doubling to 5 s, reset once it reached ready), each time on fresh snapshots: nothing is replayed. `[test]`
